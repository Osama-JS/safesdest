- Accept: application/json

    "phone": "1234567890",
    "phone_code": "+966",

    "c_address": "عنوان الشركة (اختياري)",

    "device_id": "device_unique_id (اختياري)",
    "app_version": "1.0.0 (اختياري)"
}

📤 Request Body (With Additional Fields):
{
    "name": "اسم العميل",
    "email": "customer@example.com",
    "phone": "1234567890",
    "phone_code": "+966",
    "password": "password123",
    "confirm-password": "password123",
    "c_name": "اسم الشركة",

    "additional_fields": {
        "field_name": "field_value",
        "file_field": "file_upload",
        "image_field": "image_upload"
    }
}

📥 Response (Success - 200):
{
    "status": 200,
    "message": "Your Account Created successfully"
}

📥 Response (Validation Error - 422):
{
    "status": 422,
    "errors": {
        "email": ["The email field is required."],
        "password": ["The password field is required."],
        ..

{
    "status": 500,
    "message": "Error message"

📝 7. ADDITIONAL NOTES

🔹 Authentication:
- جميع الـ protected routes تتطلب Bearer Token في header
- Token يتم الحصول عليه من endpoint تسجيل الدخول
- Token يجب أن يبدأ بـ "Bearer " متبوعاً بالـ token

🔹 File Uploads:
- الصور: jpeg, png, jpg (max 2MB)
- الملفات: pdf, doc, docx, xls, xlsx, txt, csv, jpeg, png, jpg, webp, gif (max 10MB)

- النظام يدعم قوالب ديناميكية للحقول الإضافية
- الحقول يمكن أن تكون: text, number, url, date, file, image, file_expiration_date, file_with_text

🔹 Response Format:
- جميع الـ responses تأتي بصيغة JSON
- Status codes تتبع HTTP standards
- Error messages باللغة الإنجليزية

🔹 Security:
- Rate limiting مطبق على جميع الـ authentication endpoints
