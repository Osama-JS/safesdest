🔧 إصلاح خطأ List vs Map

SafeDest Driver App - حل مشكلة type 'List<dynamic>' is not a subtype of type 'Map<String, dynamic>'
تاريخ الإصلاح: 21 سبتمبر 2025 | المطور: Augment Agent

🚨تحليل الخطأ

type 'List<dynamic>' is not a subtype of type 'Map<String, dynamic>'
المشكلة الأساسية: Laravel يرسل البيانات الإضافية كـ List بدلاً من Map، مما يسبب خطأ في Flutter

🔍 السبب الجذري:

app/Models/Driver.php - السطر 174
// الكود الخطأ: return collect($this->additional_data)->filter(function ($item) use ($formFields) { return $formFields->contains(function ($field) use ($item) { return $field->label == $item['label'] && in_array($field->driver_can, ['read', 'write']); }); })->values()->all(); // ← values() يحول إلى List!

التفسير: استخدام values() يعيد ترقيم المفاتيح من 0,1,2... بدلاً من الاحتفاظ بالمفاتيح الأصلية، مما يحول البيانات من Map إلى List.

Laravel Driver Model
additional_data كـ Map: {"field1": {...}, "field2": {...}}
2
getDriverVisibleAdditionalDataAttribute()
تطبيق filter() ثم values() → تحويل إلى List: [0: {...}, 1: {...}]
3

إرسال List<dynamic> إلى Flutter
❌
Flutter Error
Flutter يتوقع Map<String, dynamic> لكن يستقبل List<dynamic>

✅الحل المطبق

تم بنجاح: إزالة values() للحفاظ على المفاتيح الأصلية وإرسال Map بدلاً من List

الإصلاح في Driver Model:

app/Models/Driver.php
public function getDriverVisibleAdditionalDataAttribute() { if (!is_array($this->additional_data)) { return []; } $formFields = $this->formTemplate?->fields ?? collect(); return collect($this->additional_data)->filter(function ($item, $key) use ($formFields) { return $formFields->contains(function ($field) use ($item) { return $field->label == $item['label'] && in_array($field->driver_can, ['read', 'write']); }); })->all(); // إزالة values() للحفاظ على المفاتيح الأصلية }

⚙التفاصيل التقنية

🔍 الفرق بين values() و all():

📋 values() Method:

  • الوظيفة: إعادة ترقيم المفاتيح من 0, 1, 2...
  • النتيجة: تحويل Map إلى List
  • الاستخدام: عندما تريد array مرقم
  • مثال: {"a": 1, "b": 2} → [0: 1, 1: 2]

📋 all() Method:

  • الوظيفة: الاحتفاظ بالمفاتيح الأصلية
  • النتيجة: الاحتفاظ بـ Map
  • الاستخدام: عندما تريد الاحتفاظ بالمفاتيح
  • مثال: {"a": 1, "b": 2} → {"a": 1, "b": 2}

🎯 لماذا Flutter يحتاج Map:

// في Flutter AdditionalDataScreen: ..._additionalData!.entries.map((entry) { return _buildDataField(entry.key, entry.value); // يحتاج key و value }) // entry.key يحتاج اسم الحقل (String) // entry.value يحتاج بيانات الحقل (Map) // إذا كانت البيانات List، فلن يكون هناك key مفيد
