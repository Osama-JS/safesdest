ما هي منصة أمن؟

فهم طبيعة المنصة ومكانتها في السوق

ℹ️

تعريف منصة أمن

منصة أمن (Amnn) هي خدمة وساطة مالية (Escrow Service) سعودية تعمل كـ"طرف ثالث موثوق" بين البائع والمشتري في أي صفقة تجارية رقمية. المنصة تحتجز مبلغ الصفقة في حساب ضمان آمن حتى يتم تنفيذ الخدمة أو تسليم المنتج بشكل صحيح ثم تحرر الأموال للبائع. تعمل تحت مسمى "متعهد" التجاري وتستهدف منصات التجارة الإلكترونية والخدمات الرقمية ومنصات التوصيل والنقل.

🏦

خدمة الضمان المالي

تحتجز المنصة أموال المشتري في حساب مستقل وآمن طوال فترة تنفيذ الصفقة، مما يضمن عدم وصول البائع للمال قبل اكتمال الخدمة.

🤝

الوسيط الموثوق

تعمل كـ"حكم مستقل" بين البائع والمشتري مع نظام نزاعات (Dispute) واضح يحمي حقوق الطرفين في حالة الخلاف.

⚡

ربط برمجي (API-First)

تتيح للمنصات الخارجية ربط خدماتها بالكامل عبر API موثقة، مع بيئة Sandbox للاختبار وبيئة Live للإنتاج.

🇸🇦

مخصصة للسوق السعودي

تدعم المدن السعودية والأرقام السعودية وطرق الدفع المحلية (مدى، Apple Pay، Visa) مع تحويل بنكي عبر IBAN.

كيف تعمل المنصة؟

الآلية التقنية والمنطق التشغيلي خطوة بخطوة

👤

1. تسجيل الأطراف

يتم تسجيل كل من البائع والمشتري كـ"عملاء" (Customers) في نظام أمن عبر الـ API. كل عميل يحصل على رقم فريد مثل IC-0001.

📋

2. إنشاء العقد

تُنشئ المنصة عقداً رقمياً (Deal) يحتوي على تفاصيل الخدمة أو المنتج والسعر والأطراف المشاركة.

💳

3. الدفع الآمن

يدفع المشتري عبر HyperPay (مزود الدفع المعتمد). تذهب الأموال لحساب ضمان أمن وليس مباشرة للبائع.

✅

4. تحرير الأموال

بعد تأكيد التسليم تُحرر الأموال للبائع. في حالة النزاع تتدخل المنصة وتُعيد الأموال للمشتري أو تحلّ بالتفاوض.

🔄

دورة حياة الصفقة الكاملة

من لحظة إنشاء العقد حتى تسوية الأموال النهائية

1

إنشاء الصفقة draft

يتم إنشاء مسودة الصفقة عبر API مع تحديد نوعها (خدمة أو منتج) وعنوانها ووصفها والسعر الأولي. الصفقة قابلة للتعديل والحذف بالكامل في هذه المرحلة.

2

إضافة الأطراف draft

يتم تحديد المشتري (Buyer) والبائع (Seller) من قائمة العملاء المسجلين. يمكن إضافة وسيط (Broker) كطرف ثالث اختياري.

3

إرسال للموافقة requested

بعد الانتهاء من التفاصيل يتم إرسال الصفقة (Submit) فتتحول حالتها إلى "مطلوبة" في انتظار موافقة البائع.

4

موافقة البائع payment_pending

البائع يوافق (Approve). في الخدمات يمكنه تحديد السعر النهائي هنا. تتحول الصفقة لـ"بانتظار الدفع".

5

دفع المشتري paid

المشتري يدفع عبر HyperPay أو المحفظة. الأموال تذهب لحساب الضمان في أمن وتتحول الحالة إلى "مدفوعة".

6

بدء التنفيذ executing

يبدأ البائع في تقديم الخدمة أو تسليم المنتج. يعلم البائع أن المبلغ محجوز وسيصل عند الإتمام.

7

الاكتمال executed → completed

بعد تأكيد التسليم تتحول للـ executed ثم completed. يتم تحويل الأموال للبائع عبر transfer-seller-amount API.

!

النزاع (اختياري) disputed

إذا لم يكن المشتري راضياً يفتح نزاعاً مع إرفاق أدلة (صور/فيديو حتى 3 مرفقات). فريق أمن يتدخل ويتخذ القرار النهائي.

ثقة العملاء

عندما يعرف المشتري أن ماله محتجز في حساب ضمان موثوق ولن يصل للبائع إلا بعد تأكيد الاستلام، يزداد استعداده للدفع ويقل التردد.

📈

رفع معدل إتمام الصفقات

الصفقات التي تمر عبر ضمان مالي تُكمَل بنسبة أعلى لأن كلا الطرفين محميان قانونياً ومالياً مما يقلل من الانسحاب في المنتصف.

⚖️

حل النزاعات باحترافية

بدلاً من الجدل بين العميل والسائق، تتدخل منصة أمن كجهة محايدة مع إمكانية إرفاق أدلة لحسم النزاع بعدالة.

🏗️

بنية تحتية جاهزة

لا تحتاج لبناء نظام دفع وضمان من الصفر. منصة أمن توفر كل ذلك كخدمة (Escrow-as-a-Service) مع توثيق API كامل.

🔗

تكامل أمن مع منصة سيف ديست

الخطوات التقنية والفرص الفعلية للاستفادة من المنصة

✅

الخدمة جاهزة مبدئياً

تم إنشاء خدمة MtahdService.php داخل مجلد app/Services/ بمنصة سيف ديست تشمل الدوال الأساسية للربط مع API أمن.

app/Services/MtahdService.php
// المصادقة: X-API-Token
$this->apiToken = env('MTAHD_API_TOKEN', 'c2199c8e...');
$this->baseUrl  = env('MTAHD_BASE_URL', 'https://sandbox-api.amnn.sa/api/v1');

// الدوال المتاحة:
createCustomer(array $data)        // تسجيل عميل (مشتري أو بائع)
createDeal(array $data)            // إنشاء صفقة جديدة
addDealParties($dealNumber, ...)   // ربط المشتري والبائع
submitDeal($dealNumber)            // إرسال الصفقة للموافقة
getDealDetails($dealNumber)        // الاستعلام عن حالة الصفقة
🚛

حماية طلبات الشحن

عند إنشاء طلب شحن، يدفع العميل المبلغ لحساب ضمان أمن بدلاً من دفعه مباشرة للسائق. المبلغ يُحرَّر للسائق فقط بعد تأكيد الوصول.

🤝

حماية عمولات الوسطاء

الوسطاء يدخلون كـ Broker في صفقات أمن، مما يضمن استلام عمولاتهم بشفافية بعد اكتمال الصفقة دون الحاجة للتفاوض لاحقاً.

💼

عقود B2B آمنة

الشركات التي تستخدم سيف ديست لشحنات ضخمة يمكنها إنشاء عقود ضمان لمبالغ كبيرة مما يرفع مستوى الثقة بشكل كبير.

📊

لوحة مراقبة مالية

يمكن عرض رصيد الـ Escrow والأموال المحتجزة والأموال المتاحة في لوحة الإدارة لمتابعة التدفق المالي فورياً.

⚠️

نقاط مهمة قبل التطبيق الفعلي

١. المفتاح الحالي هو مفتاح Sandbox للاختبار فقط — يجب طلب مفتاح Live قبل الإنتاج.
٢. يجب تسجيل رابط Webhook الخاص بسيف ديست في لوحة تحكم أمن لاستقبال التحديثات التلقائية.
٣. عمولة منصة أمن على كل صفقة يجب مناقشتها في اتفاقية الشراكة.
