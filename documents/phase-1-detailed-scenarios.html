سيناريوهات إغلاق الإعلانات وإدارة المهام

تحليل مفصل للسيناريوهات المختلفة وخطة التنفيذ المحدثة

إجابات شاملة على الأسئلة المطروحة مع اقتراحات محسنة

السؤال الأول: ماذا يحدث للمهمة عند إغلاق الإعلان يدوياً؟

السيناريو الحالي:

عند قبول عرض → تحديث حالة المهمة إلى 'assign' → وضع السعر → بدء تنفيذ المهمة
السؤال: ماذا يحدث عند الإغلاق اليدوي للإعلان؟

الإجابة والتحليل: اقتراحك ممتاز ومنطقي

تقييم اقتراحك:

اقتراحك بمنح خيارين لصاحب المهمة عند الإغلاق اليدوي هو ممتاز ومنطقي جداً ويغطي جميع الحالات المحتملة بطريقة مرنة وعملية.

الخيارات المقترحة (موافق عليها):
الخيار الأول: إلغاء المهمة
  • الحالة الجديدة: 'cancelled'
  • المعنى: المهمة ملغية نهائياً
  • الاستخدام: عندما لا تعود المهمة مطلوبة
  • التسجيل: في history مع سبب الإلغاء
الخيار الثاني: تعليق المهمة
  • الحالة الجديدة: 'pending'
  • المعنى: المهمة معلقة مؤقتاً
  • الاستخدام: عندما تحتاج تعديل التسعير أو الشروط
  • المتطلب: إعادة تحديد طريقة التسعير
  • التسجيل: في history مع سبب التعليق

اقتراح محسن: إضافة خيار ثالث

الخيار الثالث المقترح: إعادة الإعلان
  • الحالة الجديدة: 'advertised' (مع إعادة فتح الإعلان)
  • المعنى: إعادة فتح الإعلان بنفس الشروط أو شروط معدلة
  • الاستخدام: عندما لا تعجب العروض الحالية
  • المميزات:
    • إمكانية تعديل نطاق الأسعار
    • إمكانية تعديل وصف الإعلان
    • إعادة تعيين تاريخ انتهاء جديد
    • حذف العروض السابقة أو الاحتفاظ بها
مميزات الخيار الثالث:
  • مرونة أكبر في إدارة الإعلانات
  • عدم فقدان المهمة
  • إمكانية تحسين شروط الإعلان
  • جذب عروض أفضل
اعتبارات:
  • قد يطيل عملية إنجاز المهمة
  • يحتاج واجهة إضافية للتعديل
  • قد يربك السائقين

كود التنفيذ المقترح

// وظيفة إغلاق الإعلان مع الخيارات public function closeAd(Request $request, $id) { $validator = Validator::make($request->all(), [ 'action' => 'required|in:cancel,pending,re_advertise', 'reason' => 'required|string|max:500', 'new_min_price' => 'nullable|numeric|min:1', 'new_max_price' => 'nullable|numeric|min:1', 'new_description' => 'nullable|string|max:1000' ]); DB::beginTransaction(); try { $ad = Task_Ad::with('task')->findOrFail($id); $task = $ad->task; switch ($request->action) { case 'cancel': $task->update(['status' => 'cancelled']); $ad->update([ 'status' => 'closed', 'closure_reason' => 'cancelled_by_owner' ]); break; case 'pending': $task->update(['status' => 'pending']); $ad->update([ 'status' => 'closed', 'closure_reason' => 'pending_for_modification' ]); break; case 're_advertise': // تحديث الإعلان بالشروط الجديدة $updateData = [ 'status' => 'running', 'expires_at' => Carbon::now()->addHours(24) ]; if ($request->new_min_price) { $updateData['lowest_price'] = $request->new_min_price; } if ($request->new_max_price) { $updateData['highest_price'] = $request->new_max_price; } if ($request->new_description) { $updateData['description'] = $request->new_description; } $ad->update($updateData); $task->update(['status' => 'advertised']); break; } // تسجيل في التاريخ $task->history()->create([ 'action_type' => 'ad_closed', 'description' => "Ad closed with action: {$request->action}. Reason: {$request->reason}", 'ip' => IpHelper::getUserIpAddress(), 'user_id' => Auth::id() ]); DB::commit(); return response()->json(['status' => 1, 'success' => __('Ad closed successfully')]); } catch (Exception $ex) { DB::rollBack(); return response()->json(['status' => 2, 'error' => $ex->getMessage()]); } }

السؤال الثاني: ماذا يحدث للإعلانات بعد الإغلاق والإشعارات؟

الأسئلة المطروحة:
  • ماذا يحدث للإعلانات بعد إغلاقها (يدوي/تلقائي)؟
  • كيف يتم إشعار أصحاب العروض بالقبول/الرفض؟

الإجابة: استراتيجية شاملة لإدارة الإعلانات والإشعارات

1. ما يحدث للإعلانات بعد الإغلاق:
1
الاحتفاظ بالبيانات للأرشفة
  • عدم حذف الإعلان أو العروض
  • تغيير الحالة إلى 'closed'
  • تسجيل تاريخ ووقت الإغلاق
  • تسجيل سبب الإغلاق
2
تحديث حالات العروض
  • العرض المقبول: حالة 'accepted'
  • العروض الأخرى: حالة 'rejected'
  • تسجيل تاريخ القبول/الرفض
  • تسجيل سبب الرفض إن وجد
3
إرسال الإشعارات
  • إشعار السائق المقبول عرضه
  • إشعار السائقين المرفوضين
  • إشعار صاحب المهمة بالإغلاق
4
الأرشفة والتقارير
  • نقل البيانات لجداول الأرشيف (اختياري)
  • إنشاء تقارير الأداء
  • حفظ الإحصائيات

نظام الإشعارات المقترح

للسائق المقبول:
  • إشعار فوري (Push/SMS)
  • إيميل تفصيلي
  • تفاصيل المهمة كاملة
  • معلومات التواصل
للسائقين المرفوضين:
  • إشعار مهذب
  • شكر على المشاركة
  • دعوة لإعلانات أخرى
  • نصائح لتحسين العروض
لصاحب المهمة:
  • تأكيد الإغلاق
  • ملخص العروض
  • تفاصيل السائق المختار
  • الخطوات التالية
