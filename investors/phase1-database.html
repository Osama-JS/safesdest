هيكل قاعدة البيانات والنماذج

إنشاء وتعديل جميع الجداول اللازمة لدعم منظومة المستثمرين، مع الحفاظ على التوافق الكامل مع البنية الموجودة في SafeDest.

✏️ تعديل الجداول الموجودة

1. جدول users — إضافة حقل investor

نضيف حقلاً بوليانياً واحداً يحدد ما إذا كان المستخدم مستثمراً. هذا يحافظ على بساطة النظام ويتوافق مع حقل is_customs_clearance_agent الموجود.

// Migration: add_investor_to_users_table.php Schema::table('users', function (Blueprint $table) { $table->boolean('investor')->default(false)->after('is_customs_clearance_agent'); $table->index('investor'); // للاستعلامات السريعة });
الحقلالنوعالافتراضيالوصف
investor جديدBOOLEANfalsetrue = مستثمر، false = مستخدم عادي
ℹ️

لا نحتاج جدولاً منفصلاً للمستثمرين لأنهم يسجلون الدخول عبر نفس نظام المصادقة. الحقل البولياني كافٍ للتمييز مع الحفاظ على بساطة الـ Auth Flow.

2. جدول tasks — إضافة حقول الاستثمار

إضافة حقلين للمهام: مرجع للمستثمر الذي دفع قيمة المهمة، وحالة الدفع من محفظة الاستثمار.

// Migration: add_investor_fields_to_tasks_table.php Schema::table('tasks', function (Blueprint $table) { $table->unsignedBigInteger('investor_id')->nullable()->after('user_id'); $table->enum('investor_payment_status', [ 'none', // لم يدفع مستثمر 'paid', // تم الدفع من محفظة الاستثمار 'pending' // بانتظار الدفع (General Investor) ])->default('none')->after('investor_id'); $table->foreign('investor_id')->references('id')->on('users')->onDelete('set null'); $table->index(['investor_id', 'investor_payment_status']); });

🆕 الجداول الجديدة

3. investor_wallets — محفظة الاستثمار

مشابهة تماماً لـ user_wallets الموجودة لكن مخصصة لاستقبال مبالغ الاستثمار. كل مستثمر لديه محفظة استثمار واحدة.

الحقلالنوعالقيودالوصف
id PKBIGINTAUTO_INCREMENTالمعرف الفريد
user_id FKBIGINT UNSIGNEDUNIQUE, NOT NULLمرجع للمستثمر في جدول users
statusBOOLEANDEFAULT 1حالة المحفظة (نشطة/معطلة)
notesTEXTNULLABLEملاحظات إدارية على المحفظة
deleted_atTIMESTAMPNULLABLESoft Delete
created_at / updated_atTIMESTAMPS—تواريخ الإنشاء والتحديث
💡

لماذا جدول منفصل؟ محفظة الاستثمار تُستخدم لقبول مبالغ الاستثمار ودفع المهام، بينما user_wallets تُستخدم لاستقبال العمولات. الفصل يضمن وضوح تدفق الأموال ويسهل الاستعلامات والتقارير.

5. investment_contracts — عقود الاستثمار

يحدد نوع الاستثمار، شروط العمولة، تاريخ البدء والانتهاء، وإعدادات التخصيص لكل مستثمر.

الحقلالنوعالقيودالوصف

notesTEXTNULLABLEملاحظات إدارية
created_by FKBIGINT UNSIGNEDNOT NULLAdmin الذي أنشأ العقد

⚠️

ملاحظة مهمة: يجب أن يكون هناك عقد واحد نشط (active) لكل مستثمر في أي وقت. سيتم تطبيق هذا الشرط عبر Business Logic في الـ Controller وليس على مستوى قاعدة البيانات لمرونة أكبر.

🔗 علاقات النماذج (Eloquent Relationships)

User Model — إضافات جديدة

// في User.php — إضافة الـ fillable والعلاقات // في $fillable: 'investor', // في $casts: 'investor' => 'boolean', // علاقة محفظة الاستثمار (واحد لواحد) public function investorWallet() { return $this->hasOne(InvestorWallet::class, 'user_id'); } // علاقة عقود الاستثمار (واحد لكثير) public function investmentContracts() { return $this->hasMany(InvestmentContract::class, 'user_id'); } // الحصول على العقد النشط public function activeInvestmentContract() { return $this->hasOne(InvestmentContract::class, 'user_id') ->where('status', 'active') ->where('start_date', '<=', now()) ->where(function($q) { $q->whereNull('end_date') ->orWhere('end_date', '>=', now()); }); } // Scope للمستثمرين فقط public function scopeInvestors($query) { return $query->where('investor', true); }

Task Model — إضافات جديدة

// في Task.php // في $fillable إضافة: 'investor_id', 'investor_payment_status', // العلاقة مع المستثمر public function investor() { return $this->belongsTo(User::class, 'investor_id'); } // Scope للمهام غير المدفوعة من مستثمر public function scopeAvailableForInvestorPayment($query) { return $query ->where('investor_payment_status', 'none') ->where('closed', false) ->whereIn('payment_status', ['unpaid', 'partial']); }
