أحتاج تحليلًا عميقًا لمشكلة HyperPay في Laravel.

هذه هي خدمة HyperPay الحالية (HyperpayService.php)، ويبدو أن دالة Status Query لا ترسل shopperResultUrl إطلاقًا:

```php
// ضع هنا الكود الكامل الذي أرسلته
```

لكن HyperPay يرجع الخطأ التالي أثناء payment status query:

```json id="ulx2tm"
{
  "result": {
    "code": "200.300.404",
    "description": "invalid or missing parameter",
    "parameterErrors": [
      {
        "name": "shopperResultUrl",
        "message": "was already set and cannot be overwritten"
      }
    ]
  }
}
```

المطلوب منك:

1. تحليل الكود الحالي بالكامل.
2. تحديد كيف يمكن أن يتم إرسال shopperResultUrl رغم أن getPaymentStatus لا يرسله.
3. البحث عن:

   * Middleware
   * Base HTTP Client
   * Traits
   * Macros
   * Helpers
   * Global request mergers
   * cURL wrappers
   * أي مكان يضيف parameters تلقائيًا.
4. التحقق هل هناك:

   * POST بدل GET
   * إعادة استخدام payload سابق
   * mutation للـ URL
   * request interceptor
   * config merge
5. اقتراح Logging إضافي لمعرفة الـ final URL النهائي المرسل فعليًا إلى HyperPay.
6. تعديل الكود بحيث:

   * يتم إرسال shopperResultUrl فقط في createCheckout().
   * لا يظهر أبدًا في:

     * getPaymentStatus()
     * getPaymentStatusByResourcePath()
7. أضف حماية defensive programming تمنع تمرير shopperResultUrl في أي status query مستقبلًا حتى لو تم تمريره بالخطأ.

أريد:

* شرح السبب الحقيقي المتوقع.
* الكود النهائي بعد الإصلاح.
* أفضل طريقة لتسجيل الـ outgoing request كاملة في Laravel.
