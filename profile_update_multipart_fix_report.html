⚠تحليل المشكلة

المشكلة الأساسية: فشل validation عند إرسال صورة مع بيانات تحديث الملف الشخصي

الأعراض المرصودة:

  • تحديث بدون صورة: يعمل بنجاح ✅
  • تحديث مع صورة: يفشل مع "Validation failed" ❌
  • رسالة الخطأ: البيانات المطلوبة (name, email, phone, address) مفقودة
  • في Debug: البيانات موجودة فعلياً في الطلب

السبب الجذري:

Laravel لا يدعم طلبات PUT مع multipart/form-data بشكل طبيعي. عندما يتم إرسال طلب PUT مع ملفات، Laravel لا يستطيع قراءة البيانات النصية بشكل صحيح.

API Response Body: { "success": false, "message": "Validation failed", "errors": { "name": ["The name field is required."], "email": ["The email field is required."], "phone": ["The phone field is required."], "address": ["The address field is required."] } }

✓الحل المطبق

الحل: تحويل طلب PUT إلى POST مع إضافة _method=PUT للتوافق مع Laravel

1. تحديث ApiService في Flutter

safedest_driver/lib/services/api_service.dart

تم تعديل دالة putWithFile لاستخدام POST بدلاً من PUT:

// PUT request with file upload (using POST with _method=PUT for Laravel compatibility) Future> putWithFile( String endpoint, { Map? body, Map? files, T Function(dynamic)? fromJson, }) async { try { final uri = _buildUri(endpoint, null); final request = http.MultipartRequest('POST', uri); // Use POST instead of PUT // Add headers request.headers.addAll(_authHeaders); // Add _method field to simulate PUT request request.fields['_method'] = 'PUT'; // Add files and body fields... } }

2. إضافة Route بديل في Laravel

routes/api_driver.php

تم إضافة route إضافي يدعم POST مع _method=PUT:

Route::put('/profile', [DriverProfileController::class, 'update']) ->name('api.driver.profile.update'); // Alternative route for multipart form data (POST with _method=PUT) Route::post('/profile', [DriverProfileController::class, 'update']) ->name('api.driver.profile.update.multipart');

3. تحسين Logging في Controller

app/Http/Controllers/Api/DriverProfileController.php

تم إضافة logging مفصل لتتبع البيانات المرسلة:

// Log incoming request data for debugging Log::info('Driver profile update request', [ 'driver_id' => $driver->id, 'request_method' => $request->method(), 'content_type' => $request->header('Content-Type'), 'has_files' => $request->hasFile('image'), 'all_data' => $request->all(), 'files' => $request->allFiles(), ]);

🔬التفاصيل التقنية

لماذا لا يعمل PUT مع multipart/form-data؟

السبب التقني: HTTP PUT مع multipart/form-data ليس مدعوماً بشكل كامل في معظم frameworks بما في ذلك Laravel. البيانات النصية تضيع أثناء parsing.

الحلول البديلة المتاحة:

  • POST مع _method=PUT: الحل المطبق - يحاكي PUT باستخدام POST
  • استخدام POST مباشرة: تغيير الـ endpoint إلى POST
  • فصل رفع الصورة: endpoint منفصل للصور
  • Base64 encoding: تحويل الصورة إلى نص (غير مفضل للصور الكبيرة)

مزايا الحل المطبق:

  • توافق كامل: يعمل مع Laravel بدون مشاكل
  • RESTful: يحافظ على مبادئ REST API
  • شفافية: Laravel يتعامل معه كـ PUT request
  • عدم كسر التوافق: الـ routes القديمة تعمل للطلبات بدون ملفات
