🚛 تقرير شامل لنظام إعلانات المهام

تحليل مفصل لنظام Task Ads في مشروع SafeDest وخطة التطوير الكاملة

تاريخ التقرير: 8 سبتمبر 2025

📋 الملخص التنفيذي

نظام إعلانات المهام (Task Ads) هو نظام متقدم يسمح للعملاء بنشر مهام النقل كإعلانات عامة، حيث يمكن للسائقين تقديم عروض أسعار تنافسية لتنفيذ هذه المهام. النظام مطبق بالكامل في لوحة التحكم الخاصة بالسائق ويحتاج إلى تطوير APIs ومن ثم تطبيق Flutter متكامل.

🎯 الهدف الرئيسي

تطوير نظام إعلانات المهام في تطبيق Flutter للسائق مع الحفاظ على نفس الوظائف الموجودة في لوحة التحكم

📊 النطاق

تطوير APIs + تطبيق Flutter + تكامل كامل مع النظام الحالي

⏱️ المدة المتوقعة

5-7 أيام عمل (Backend + Frontend + Testing)

🔍 تحليل النظام الحالي

📊 هيكل قاعدة البيانات

🗃️ جدول tasks_ads

id (Primary Key) task_id (Foreign Key → tasks) description (وصف الإعلان) status (running/closed) highest_price (أعلى سعر) lowest_price (أقل سعر) included (شامل الضريبة) closed_at (تاريخ الإغلاق) service_commission (عمولة الخدمة) service_commission_type (نوع العمولة) vat_commission (عمولة الضريبة)

🗃️ جدول tasks_offers

id (Primary Key) task_ad_id (Foreign Key → tasks_ads) driver_id (Foreign Key → drivers) price (سعر العرض) description (وصف العرض) accepted (مقبول/مرفوض)

🔗 العلاقات بين الجداول

Task → Task_Ad: علاقة واحد لواحد - كل مهمة يمكن أن تصبح إعلان واحد
Task_Ad → Task_Offers: علاقة واحد لمتعدد - كل إعلان يمكن أن يحتوي على عروض متعددة
Driver → Task_Offers: علاقة واحد لمتعدد - كل سائق يمكن أن يقدم عروض متعددة

👨‍💼 تحليل عمليات السائق في لوحة التحكم

📍 المسار: /driver/ads - لوحة التحكم الخاصة بالسائق

🔧 العمليات الأساسية

  • 1. عرض قائمة الإعلانات المتاحة

    عرض الإعلانات المناسبة لحجم مركبة السائق مع إمكانية الفلترة والبحث

    GET /driver/ads/data
  • 2. عرض تفاصيل الإعلان

    عرض تفاصيل المهمة، نقاط الاستلام والتسليم، والبيانات الإضافية

    GET /driver/ads/show/{id}
  • 3. تقديم عرض سعر

    تقديم عرض سعر مع وصف للمهمة

    POST /driver/ads/offers/store
  • 4. تعديل العرض المقدم

    تعديل السعر أو الوصف للعرض المقدم مسبقاً

    POST /driver/ads/offers/store (with ID)
  • 5. عرض العروض المقدمة

    عرض جميع العروض المقدمة من السائقين الآخرين

    GET /driver/ads/offers/show
  • 6. قبول المهمة بعد الموافقة على العرض

    قبول تنفيذ المهمة عند موافقة العميل على العرض

    GET /driver/ads/offers/accept/task/{id}

🧠 منطق العمل والقواعد

📋 قواعد عرض الإعلانات

🚛 فلترة حسب حجم المركبة

يتم عرض الإعلانات التي تتطابق مع حجم مركبة السائق فقط

whereHas('task', function ($q) use ($size_id) { $q->where('vehicle_size_id', $size_id); });

📊 فلترة حسب الحالة

عرض الإعلانات الجارية + الإعلانات المغلقة التي قدم فيها السائق عرضاً

// إعلانات جارية $q->where('status', 'running') // أو إعلانات مغلقة مع عروض السائق ->orWhere(function ($subQ) use ($driver_id) { $subQ->where('status', 'closed') ->whereHas('offers', function ($offerQ) use ($driver_id) { $offerQ->where('driver_id', $driver_id); }); });

🔐 قواعد الصلاحيات

عرض التفاصيل: يمكن للسائق عرض تفاصيل الإعلان إذا كان جارياً أو إذا قدم عرضاً فيه
تقديم العرض: يمكن تقديم عرض فقط للإعلانات الجارية وبدون عرض مقبول
تعديل العرض: يمكن تعديل العرض فقط إذا لم يتم قبوله بعد
قبول المهمة: يمكن قبول المهمة فقط إذا تم قبول عرض السائق من قبل العميل

💰 حساب الأسعار والعمولات

معادلة حساب صافي مستحقات السائق:

$price = $offer->price; // سعر العرض $commissionType = $ad->service_commission_type; // نوع العمولة (0=نسبة، 1=مبلغ ثابت) $commissionValue = $ad->service_commission; // قيمة العمولة $vat = $ad->vat_commission; // ضريبة القيمة المضافة // حساب العمولة $commission = $commissionType === 1 ? $commissionValue : ($price * $commissionValue / 100); // حساب الضريبة $vatAmount = $price * $vat / 100; // إجمالي الخصومات $deduction = $commission + $vatAmount; // صافي المستحقات $net = $price - $deduction;

  • الصور والملفات

  • عرض تفاعلي حسب نوع البيانات

💰 قسم العروض

مكونات قسم العروض:

  • نموذج تقديم/تعديل العرض: سعر + وصف + حساب صافي المستحقات
  • عرض العروض المقدمة: قائمة جميع العروض مع تمييز عرض السائق
  • حالة العرض: مقدم/مقبول/مرفوض
  • زر قبول المهمة: يظهر عند قبول العرض من العميل

🔧 خطة تطوير APIs

✅ الحالة الحالية: تم إنشاء DriverTaskAdsController جزئياً مع بعض الـ APIs الأساسية

📋 APIs المطلوب تطويرها

العملية HTTP Method Endpoint الحالة
جلب قائمة الإعلانات GET /api/driver/task-ads موجود
تفاصيل إعلان محدد GET /api/driver/task-ads/{id} موجود
تقديم عرض POST /api/driver/task-ads/{id}/offers موجود
تعديل عرض PUT /api/driver/offers/{id} موجود
جلب عروض إعلان GET /api/driver/task-ads/{id}/offers مطلوب
جلب عروضي GET /api/driver/my-offers موجود
قبول المهمة POST /api/driver/offers/{id}/accept موجود

📋 الخلاصة والتوصيات

🎯 ملخص المشروع

نظام إعلانات المهام هو نظام متكامل ومعقد يتطلب تطوير دقيق للحفاظ على نفس مستوى الوظائف الموجودة في لوحة التحكم. النظام الحالي مطبق بشكل ممتاز في الواجهة الويب ويحتاج إلى نقل هذه الوظائف بدقة إلى تطبيق Flutter.

✅ النقاط الإيجابية

  • نظام محكم:

    منطق العمل والقواعد محددة بوضوح مع معالجة شاملة للحالات المختلفة

  • APIs جاهزة جزئياً:

    معظم APIs الأساسية موجودة ويحتاج فقط إضافة API واحد

  • تطبيق Flutter متقدم:

    التطبيق له هيكل ممتاز ويسهل إضافة الوظائف الجديدة

⚠️ التحديات المتوقعة

  • تعقيد حساب الأسعار:

    نظام العمولات والضرائب معقد ويحتاج تطبيق دقيق

  • إدارة الحالات:

    حالات العروض والإعلانات متعددة وتحتاج معالجة شاملة

  • تجربة المستخدم:

    الحفاظ على نفس مستوى التفاعل والسهولة الموجود في الويب

🚀 التوصيات

  • البدء بـ APIs: إكمال جميع APIs المطلوبة واختبارها جيداً
  • التطوير التدريجي: تطوير الشاشات واحدة تلو الأخرى مع الاختبار المستمر
